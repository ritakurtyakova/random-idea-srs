# Процесс проектирования и нормализации базы данных

## 1. Исходная (денормализованная) структура

Для демонстрации проблем была рассмотрена условная таблица `Ideas_Flat`, содержащая все данные приложения «Генератор случайных идей»:

`Ideas_Flat (idea_id, content, genre_name, content_type, seed, favorite)`

В таблице хранятся текст идеи, название жанра, тип генерации, зерно генерации и информация об избранном.

**Проблемы исходной структуры:**

- **Избыточность:** названия жанров повторяются для разных идей.
- **Аномалия обновления:** при изменении названия жанра необходимо обновлять несколько записей.
- **Аномалия удаления:** при удалении последней идеи определённого жанра можно потерять информацию о самом жанре.

Для устранения этих проблем необходимо разделить данные на несколько связанных таблиц и провести нормализацию до третьей нормальной формы (3NF).

## 2. Первая нормальная форма (1NF)

Для приведения структуры к первой нормальной форме необходимо обеспечить атомарность значений в каждом поле.

В исходной структуре данные об идее, жанре и типе генерации хранились в одной таблице. Кроме того, одна генерация может возвращать несколько результатов. Если хранить все результаты в одном поле через запятую или другой разделитель, нарушается требование атомарности.

Для устранения этой проблемы данные разделяются на две таблицы:

- `Generation` — хранит информацию о процессе генерации: жанр, тип генерируемого содержимого, seed, уровень абсурдности и дату создания.
- `GeneratedIdea` — хранит отдельные результаты генерации. Каждая идея записывается в отдельную строку и связывается с генерацией через `generation_id`.

Таким образом, каждое поле содержит одно значение, а несколько результатов одной генерации представлены отдельными записями.

**Вывод:** структура приведена к первой нормальной форме (1NF), поскольку значения атрибутов атомарны, а повторяющиеся группы данных вынесены в отдельную таблицу.
